> “Modern LLMs are mostly built by stacking transformer blocks over and over.”

这句话基本就是整篇文章的轴心：现代 LLM 的大部分机制，都可以理解为把文本变成 token，把 token 变成向量，再让向量反复经过 Transformer block，最后预测下一个 token。

## 一句话结论

LLM 不是一次性“想出一整段话”的系统。

它更像一个反复更新状态的序列机器：

1. 把文本切成 token ID；
2. 把 token ID 查表变成 embedding vector；
3. 加入位置信息；
4. 在 Transformer 层里让 token 通过 attention 交换信息；
5. 用 feed-forward network 对每个 token 各自加工；
6. 通过 residual stream 和 normalization 保持深层网络可训练；
7. 把最后一个 token 的最终向量变成 vocabulary 上的 logits；
8. 采样一个新 token；
9. 把新 token 接回输入，再跑一轮。

这就是生成循环。段落、回答、代码和长文本，本质上都是这个循环一 token 一 token 运行出来的。

## 1. Tokenization：模型读的不是字，而是整数

原文的第一个关键点是：模型不直接读文本。它读的是整数 ID。

Tokenizer 会把字符串转换成一串 token IDs。每个 ID 对应 tokenizer vocabulary 里的一个条目。现代 LLM 的 vocabulary 往往有几万到几十万个 entry。

这里最容易误解的是 token 和 word 的关系。Token 通常不是完整单词，而是 subword pieces。比如一个词可能被切成常见词根和后缀；罕见词也可以由更小片段拼出来。

这种设计是在三件事之间折中：

- whole-word vocabulary 太大，也不容易泛化到新词；
- character-level vocabulary 太小，会让序列很长，也让模型从字符层重新学简单模式；
- subword tokenization 既能压缩常见片段，又能组合罕见词。

所以模型在处理某些“字母级问题”时会显得奇怪。它不是天然在 letter 上操作，而是在 token ID 上操作。

## 2. Embeddings：整数查表，变成可计算的向量

Token ID 本身没有语义，它只是行号。

Embedding matrix 是一张巨大的 lookup table。每个 vocabulary entry 对应一行，每一行是一条长向量。分词器给出 token ID 后，模型查出对应的向量，把离散 ID 变成连续数值表示。

这个阶段有两个重点。

第一，embedding 是模型学习出来的语义几何。语义接近或用法接近的 token，往往在向量空间里更接近。经典类比是 king、queen、man、woman 之间的向量关系。

第二，embedding 本身只表达 token “是什么”，不表达 token “在哪里”。同一个 token 出现在句首和句尾，起始 embedding 是同一个。

这就需要位置编码。

## 3. Positional encoding：顺序必须注入进数学里

Self-attention 本身没有天然词序感。如果没有位置信号，它并不知道一个词是在另一个词前面还是后面。

原始 Transformer 使用 sinusoidal positional encoding：给每个位置一组由正弦和余弦构成的数字模式，再把这组模式加到 token embedding 上。

现代 LLM 更常见的是 RoPE，也就是 Rotary Position Embeddings。

RoPE 的直觉是：不要把位置向量直接加到 token 表示上，而是根据位置旋转 Query 和 Key 向量。之后 attention 比较 Query 和 Key 时，相对距离就会自然进入计算。

这比绝对位置 embedding 更贴近 attention 的需求，也更适合长上下文扩展。

但位置编码并没有彻底解决长上下文问题。原文提到的 “lost in the middle” 很重要：模型对提示词开头和结尾的信息通常更可靠，对埋在中间的信息使用得更差。

这也是为什么实践里经常要把重要信息放前面，或在结尾重复关键条件。

## 4. Attention：token 如何互相看见

Attention 让每个 token 查看它允许看到的其他 token，并决定哪些信息应该影响自己的下一步表示。

每个 token 会被投影成三种向量：

- Query：我在找什么；
- Key：我能和什么匹配；
- Value：匹配强时传递什么信息。

Attention 的核心计算可以粗略理解为：

1. 用 Query 去比较允许看到的 Key；
2. 得到一组匹配分数；
3. 用 softmax 把分数变成权重；
4. 按权重混合对应 Value；
5. 得到这个 token 的新信息。

GPT 风格模型还要加 causal masking。因为它从左到右生成，当前位置不能偷看未来 token。实现上就是把未来位置的匹配分数压到极低，让 softmax 后权重接近零。

原文还提到 induction heads：这是一类能识别重复模式的 attention heads。它们能看到提示词里形如 “A B … A” 的模式，然后帮助模型预测 B。这是 in-context learning 里一个很清楚的机制线索。

Attention 的代价也很直接：完整 attention 里 token 要和许多其他 token 两两比较，所以长上下文很贵。这也是 FlashAttention、sparse attention、linear attention 等优化方向的重要原因。

## 5. Multi-head attention：不是切片，而是多种学习视角

一个 attention head 只能给模型一种关系视角。语言里同时存在主谓关系、指代关系、局部短语、长距离引用、重复模式和位置模式，所以单个 head 不够。

Multi-head attention 会并行运行多个 attention heads。

一个常见误解是：每个 head 拿到原始 token vector 的一个固定切片。

更准确的说法是：每个 head 都有自己的 learned projection matrices，会把完整 token vector 投影到自己的小型 Q、K、V 空间。它们是同一个 token 的不同视角，不是不同块。

所有 heads 的输出会拼接起来，再经过一个线性层混合回完整向量。

实际运行时还有 KV cache。生成过程中，已经生成 token 的 Key 和 Value 会被缓存下来，新 token 生成时不必重算整个前缀。

但 KV cache 很占内存。Grouped-Query Attention 让多个 Query heads 共享更少的 Key/Value heads，在保留多种 Query 视角的同时降低缓存成本。

## 6. Feed-forward network：模型存放大量结构的地方

Attention 负责 token 之间的信息交换。Feed-forward network 负责每个 token 自己的进一步加工。

FFN 通常做三步：

1. 把 token vector 扩展到更宽的空间；
2. 经过非线性函数；
3. 压缩回原始隐藏维度。

非线性很关键。没有非线性，多层线性层叠在一起仍然等价于一层线性层。非线性阻止这种坍缩，让 FFN 可以表达比一次矩阵乘法更复杂的结构。

原始 Transformer 使用 ReLU，GPT/BERT 使用 GELU，现代 LLaMA、Mistral、PaLM 等模型常用 SwiGLU。结构没有变，变的是中间的非线性选择。

原文强调了一个容易被低估的点：dense transformer 里很大一部分参数在 FFN，而不是 attention。许多事实和语义结构也和 FFN 权重、激活有关。

这也解释了为什么模型编辑方法会瞄准 FFN 权重。例如 ROME 可以通过定向低秩编辑，改变模型对某些事实关联的生成倾向。

MoE 则是 FFN 的另一种扩展方式：不再每层只有一个 dense FFN，而是有多个 experts，router 为每个 token 选择少数 experts。这样总参数量可以增长，但每个 token 实际激活的计算量不会同比例增长。

## 7. Residual stream 和 layer normalization：深层模型为什么能训练

Transformer block 的输出通常不会直接替换 token vector，而是加回原 vector。

这就是 residual connection。跨越很多层之后，每层贡献会不断累积，形成 residual stream。

Residual connection 的价值是给信息和梯度一条 shortcut。没有它，非常深的网络很难训练。Transformer 从 ResNet 那里继承了这个技巧。

Layer normalization 解决的是数值稳定性。经过许多层相加后，向量里的数字可能爆炸，也可能坍缩。LayerNorm 或 RMSNorm 会把向量重新缩放到可控范围。

现代 Transformer 常用 pre-norm：在子模块之前做 normalization，而不是之后做。很多开放模型还使用 RMSNorm，去掉均值中心化，只保留重新缩放，计算更便宜。

这部分并不光鲜，但没有 residual connections 和 normalization，就没有几百层深的可训练模型。

## 8. Next-token prediction：最终输出只是 vocabulary 上的一组分数

所有 Transformer 层运行结束后，模型会取最后一个 token 的最终向量，映射成 vocabulary 中每个可能下一个 token 的 raw score。

这些 raw scores 叫 logits。

Logits 还不是概率。经过 softmax 之后，它们才成为下一个 token 的概率分布。

生成时，模型通常不会永远选择最高概率 token。temperature、top-k、top-p 会改变采样方式，让输出更保守或更多样。

一旦采样出一个 token，它会被接回输入。模型在更长序列上继续下一步，通常复用 KV cache。这个循环一直运行，直到输出结束 token 或达到长度限制。

所以一段回答不是一次性产生的，而是：

```txt
prefix -> logits -> sample token -> append token -> repeat
```

原文还提到 speculative decoding：小模型先向前草拟多个 token，大模型并行验证。做对时，输出分布和单独运行大模型一致，但速度更快。

## 9. Architecture vs trained weights：相似骨架，不同权重

在这个抽象层级上，现代 LLM 大多共享 Transformer 家族骨架：

- tokenization；
- embeddings；
- positional encoding；
- stacked transformer layers；
- multi-head attention；
- feed-forward network；
- residual stream；
- normalization；
- next-token prediction。

模型之间真正变化的是：

- 训练数据和训练规模；
- 层数、隐藏维度、词表大小、head 数、参数量；
- dense 还是 MoE；
- RoPE、RMSNorm、SwiGLU、GQA 等配置选择；
- instruction tuning、RLHF、安全对齐等后训练。

所以读现代模型卡时，可以先把它拆成两层看：

1. 架构骨架属于哪一类；
2. 权重、数据、配置和后训练让它变成了哪一种具体模型。

## 我的理解

这篇原文最有价值的地方，是它把 LLM 从“神秘会话系统”还原成一个可拆解的状态更新机器。

如果用工程视角压缩成一句话：

> LLM 的主干不是“回答问题”，而是“维护一条 token state stream，并不断把最后一个 state 映射到下一个 token 的概率分布”。

这句话能解释很多现象：

- 为什么 tokenization 会影响模型在字母级任务上的表现；
- 为什么长上下文不是简单把窗口做大；
- 为什么 KV cache 会成为推理内存大头；
- 为什么 temperature 会改变模型性格；
- 为什么同一架构下，数据、权重和后训练会造成巨大差异；
- 为什么现代模型架构看起来越来越像一套稳定工程栈。

真正的重点不是记住每个术语，而是建立这个循环：

```txt
text -> token IDs -> embeddings -> transformer layers -> logits -> sampled token -> repeat
```

只要脑子里有这条线，读大多数现代 LLM 论文、模型卡和推理优化文章时，就不容易迷路。
